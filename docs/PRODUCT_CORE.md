# 產品核心設計：今日運動處方

2026-11-15 · Claude Code 依使用者的產品重新定義整理。**只是設計，尚未實作**；開發等 Codex 的 PR #10 合併後開始。所有計算細節登記在 `docs/ALGORITHMS.md`（R11 起），經使用者核准才實作。

## 一句話

依昨天的訓練、昨晚的恢復、你本身的體能，再結合今天的天氣、空氣品質、路線坡度與地點限制，**事前**算好今天該練多少強度，並推薦一條路線與每公里配速，讓你跑完剛好就是那個強度。

和高馳「等強配速」、Stryd 功率的差別：它們是**事後**換算；AIAC 是**出門前**就把路線與環境算進處方。

儀表板（體能、健康、睡眠）照樣提供，作為參考。

## 決策流程

```
昨天訓練、昨晚恢復、體能/疲勞、計畫與目標
              │
        ① 今日強度預算 ── 課表類型、時間、目標負荷
              │
你的選擇與限制 ┤ ② 室內/戶外、運動項目、可用時間、出發時間、器材
              │
今天的環境 ────┤ ③ 環境指引：天氣、風大不大、空氣品質（建議戶外／都可以／不建議戶外）
              │
        ④ 等強換算 ── 路線每段坡度＋熱與濕度＋海拔 → 每公里配速
                      或跑步機速度與坡度
                      或替代運動（腳踏車、滑步機）的時間與心率
              │
        ⑤ 處方：路線／器材、每公里配速、心率上限、預測負荷
              │
        ⑥ AI 教練用你選的風格解釋（不改數字）
              │
跑完 ── ⑦ 預測與實際對照，校正個人模型
```

## 各元件

### ① 今日強度預算
- 輸入：昨天的負荷、昨晚睡眠與 HRV／安靜心率（準備度）、體能／疲勞／狀態、訓練計畫當天的課、目標。
- 輸出：課表類型（休息、恢復、輕鬆、節奏、間歇、長跑）、時間、目標負荷，以及**理由清單**（哪個訊號讓它降或升）。
- 規則待研究：R18。

### ② 使用者的選擇與限制（一級輸入）
- 改室內、跑步機或改騎車，**可以是使用者主觀的選擇**（下雨、地點不適合、今天就是不想跑），不只是引擎的決定。引擎在使用者選定的條件內找最合適的方案。
- 項目：室內／戶外、運動項目（跑步、跑步機、腳踏車、滑步機⋯）、可用時間、預計出發時間、不想去的地點、可用器材。
- **預設值**（2026-11-15 使用者決定，皆可修改）：出發時間 **05:30**；地點 **台北士林**。天氣與空氣品質預報依這兩個值查詢。

### ③ 環境指引（不進等強換算的部分）
- **風**：只給概念（無風／有風／強風），不逐段計算。建築物遮蔽讓逐段估算不可靠，使用者決定不做。
- **空氣品質**：用出發時段的預報，給三級指引：**建議戶外**／**室內戶外都可以**／**不建議戶外**。不換算成配速。門檻待研究：R14。
- **降雨、雷雨**：顯示預報，讓使用者決定。
- 資料：Open-Meteo 天氣與空氣品質預報（免費、不用金鑰）。拿不到資料時明說「沒有預報資料」，**不得捏造**。

### ④ 等強換算（核心計算）
同樣的「目標強度」，在不同條件下對應不同的配速或時間：

| 條件 | 換算 | 研究項目 |
|---|---|---|
| 坡度 | 路線每段坡度 → 該段等強配速 | R1 |
| 熱與濕度 | 出發時段的氣溫、濕度（WBGT 或露點）→ 配速放慢比例或心率上限 | R12 |
| 海拔 | 高海拔路線 → 配速放慢比例 | R13 |
| 跑步機 | 戶外目標 → 跑步機速度與坡度；**處方上提示「記得把坡度設 1%」**（多數使用者不知道） | R15 |
| 替代運動 | 跑步課 → 腳踏車、滑步機的時間、心率範圍與可替代程度 | R16 |

**替代運動是 AIAC 特別的地方**：使用者問「我今天不想跑，可以用滑步機或腳踏車代替嗎？」引擎要回答：
1. **可不可以替代**：輕鬆、恢復課可替代；跑步專項課（間歇、比賽配速、長跑）只能部分替代，並說明少了什麼（跑步經濟性、腿部承受衝擊的適應）。
2. **要做多久、多強**：依研究換算時間與心率範圍。沒有充分研究時，**先用經驗法則**（例如跑 1 小時 ≈ 騎 90 分鐘），寫清楚計算方式，之後用跑後校正修正。AI 教練回覆時要說明這個數字是怎麼算的、依據強弱。
3. 第一版涵蓋：**腳踏車（室內、戶外）、滑步機**（健身房常見器材）。
4. **算進負荷的方式**：跨項目負荷如何計入 CTL／ATL。

### 不輸出功率，而是用物理訊號逼近功率
多數人沒有跑步功率計，所以處方**只輸出每公里配速＋心率上限**。AIAC 的等強換算本身就是用坡度、速度、環境等物理訊號，逼近功率計直接量到的強度（2026-11-15 使用者決定）。

### ⑤ 路線推薦
- 第一階段（使用者同意）：使用者**自己跑過的 GPS 路線**（從 intervals.icu 取軌跡與高度）。熟悉、安全、資料可靠。
- 對每條候選路線，依今天的條件算出預測負荷，選最接近目標的，給每公里配速與心率上限。
- 第二階段（之後研究）：OpenStreetMap 自動產生新路線。人行道、交通、照明、安全、台灣地圖資料品質都要另外評估。

### ⑥ AI 教練
- LLM 只用使用者選的教練風格（見 `docs/COACH_STYLES.md`）解釋處方，**不計算、不改數字**。
- 只在使用者點擊時呼叫，受每日上限約束（產品紅線不變）。

### ⑦ 跑後校正
- 對照預測負荷、配速、心率與實際結果（intervals.icu 負荷、平均心率）。
- 逐步調整個人係數（例如你的坡度成本、怕熱程度、騎車與跑步的換算）。方法待研究：R17。
- 這一步讓處方越用越準。

## 開發順序（PR #10 合併後）

1. 今日強度預算＋使用者選擇＋可解釋的理由。
2. 替代運動與跑步機換算（不需地圖，最快能用，也是特色）。
3. 坡度等強：套在歷史 GPS 路線上。
4. 接 Open-Meteo：熱與濕度修正、風的概念、空氣品質指引。
5. 路線推薦與每公里配速。
6. 跑後校正。
7. 自動產生新路線（先研究）。
