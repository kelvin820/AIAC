# AIAC 開發與試用計畫

2026-11-11 · 討論稿。這份計畫不會變更線上版、搬移資料或開通外部服務。

## 目標使用流程

1. **首次設定：註冊 AIAC，選擇並授權運動資料來源。** 使用者登入手錶或運動平台對應的服務並完成配對。AIAC 顯示連線狀態和最近一次同步時間，首次同步完成後就能看到活動。
2. **日常同步：裝置 → 運動平台 → AIAC。** 運動紀錄進到已配對的平台後，由 AIAC 在背景同步。使用者不用開著 AIAC、逐筆下載或上傳檔案。AIAC 用同步到的活動更新課表實績；同一筆活動不重複計算，對應不明時才請使用者確認。
3. **日常首頁只問使用者才能回答的事。** 顯示今天原定的課和最近同步到的活動，讓使用者確認「今天有哪些設備可用？」和「今天想照原計畫運動嗎？」設備沿用上次選擇，可直接確認或修改。選擇調整時，教練根據回答、課表和已同步的實績提出替代方案，由使用者確認。
4. **例外情況才走手動流程。** 未支援的來源、同步失敗或授權失效時，顯示狀態並提供重連或重試。手動 FIT 匯入是保底，也可用來補匯舊紀錄。同步本身不觸發 LLM 呼叫。

## 推進順序

先以本機單人版、自己的 FIT 和自帶 LLM Key 驗證教練流程。接著選一個實際使用的運動平台，驗證從授權到背景同步。註冊、帳號資料隔離和雲端儲存是目標流程的基礎，排在小規模雲端測試時實作；公開推廣、正式託管與收費再依試用結果決定。

| 階段 | Codex 做什麼 | 驗收條件 | 你需要做什麼 |
|---|---|---|---|
| 0．朋友試用，建議 5–7 天 | 維持現行線上 Mock；整理回饋為阻礙操作、容易誤解、想要的功能。優先修前兩類 | 3–5 人各走一次「調課 → 接受或拒絕 → 登錄實際 → 看完成度」；至少收回能重現的操作步驟 | 分享試用網址；請朋友回報哪一步卡住、是否看得懂時間與訓練目的的差別。可用示範或手填數字，不必交出真實健康資料 |
| 1．能連續用的週計畫 | 加上前週／本週／下週、保留舊計畫和實際紀錄；改善 FIT 對應課程、重複活動提示與手機表單；加入可還原的備份匯出／匯入 | 跨過週一仍能查前週；改預計課程不改實績；同一活動匯入兩次不重算；換瀏覽器能從匯出檔復原，匯出不含 Key | 選兩週你願意用來驗證的課表。可用手填、合成 FIT，或在自己電腦用真實 FIT |
| 2．本機驗證真實 Coaching | 用同一組情境比較 Mock、真實建議和你原本會做的選擇；補足運動後比較、缺失欄位說明及調課取捨，保留呼叫上限 | 至少驗證「只剩 30 分鐘」「不想跑間歇」「本週漏課」「同一天多筆活動」；你能看懂建議為何改、刺激是否保留，且教練不會為補數字硬塞課 | 若願意測真實 LLM，在本機自行貼 Key，先用測試資料，建議上限每天 1–2 次。回報哪句理由有幫助、哪次會拒絕，無須把 Key 貼到聊天 |
| 3．打通一個運動資料來源 | 依日常使用的裝置和已有的開發者資格選來源，驗證首次同步、增量同步、重試、授權失效及撤銷 | 測試活動出現在來源平台後，AIAC 能在預定同步時間內自行讀到，並顯示最近一次同步時間。同一活動重試或以 FIT 補匯均只計一次，撤銷後停止同步 | 確認先接哪個日常來源，並登入該平台完成授權 |
| 4．邀請制雲端測試 | 新增 AIAC 註冊登入、每個帳號的來源配對與資料隔離、背景同步、資料匯出與刪除。首頁接上已同步的實績和兩個日常問題 | 兩個測試帳號各自配對，資料互相隔離。關閉 AIAC 頁面後新增一筆活動，再開首頁時能看見已同步的實績，並只需確認設備與是否照計畫運動 | 用自己的裝置完成一次配對，再走一次真實運動後的首頁流程 |

不以日曆日期強推下一階段。第一輪回饋完成後，若最大的障礙是「不知道怎麼開始」，先補一個可重做的示範；若是「用了第二週找不到上週」，先修週切換；若是「看得懂但不信建議」，把時間用在本機 Coaching 驗證。

## 資料現在存在哪裡？

| 使用方式 | 保存位置 | 原始 FIT 與金鑰 |
|---|---|---|
| GitHub Pages 線上試用 | 設定、課表、對話、記憶、活動摘要在各自瀏覽器的 `localStorage`；不跨瀏覽器或裝置同步。清網站資料會失去紀錄 | FIT 在瀏覽器內讀取解析，AIAC 只保存解析結果，不上傳、不另外保存原檔；不收 Key、不呼叫 LLM。GitHub 倉庫只有程式碼與公開素材 |
| 下載後在電腦執行 | `data/state.json` 保存設定、課表、對話、活動摘要、額度等 | 成功匯入的原 FIT 在 `data/uploads/`。Key 和 OAuth token 存於 `data/vault.enc`，本機解密金鑰為 `data/vault.key`；兩者目前同在 `data/`，應用本機帳戶權限保護 |
| 本機主動用自己的 LLM | AIAC 本機仍保存操作結果；依設定傳送必要的個人情境、部分活動摘要及對話到指定供應商 | 不送 FIT 原檔。供應商端的保存與費用依其設定；AIAC 的本機刪除不會同時刪掉供應商的資料 |

這裡的「不傳到 AIAC 伺服器」是指訓練與個人內容；和任何網站一樣，GitHub Pages 仍處理一般網站訪問。不要把 `data/`、`.env`、真實 FIT、Key 或帶有健康資訊的截圖貼到公開 GitHub Issues。若要回報解析問題，先提供錯誤文字及裝置，必要時再決定如何私下提供範例。

## 建議的保存方案

- **現在：瀏覽器試用＋單人本機。** 先加備份與還原，保留選擇權。跨週規劃初期可沿用現有 JSON；如果歷史查詢、更新衝突或遷移變得難管理，再換 SQLite。匯出可分成一般備份（不含憑證）與自選原始 FIT；清除單一活動與清除原始檔的關係要顯示清楚。
- **若進入雲端：先同步有用的摘要。** 帳戶下保存課表、活動摘要與對話；能在瀏覽器解析時就不把原始 FIT 放上雲端。使用帶帳號權限的資料庫；若確有原檔重解析需求，再加私有檔案儲存與明確期限。Key 與 OAuth token 由伺服器單獨保護，不放一般表格、前端或日誌。把個別帳號匯出、刪除、備份的保留期和復原責任列進驗收。
- **待討論的預設：** 原 FIT 上雲預設關閉；雲端同步採自願開啟。若要開放保留原檔，可先討論「只保留摘要」或「短期保留原檔以便重解析」，再定實際期限。先確認大家是否真的需要換電腦或手機後繼續，而非一開始就決定託管商。

## 可以晚點做

同時接 Garmin、Apple Health、Strava 和各種 MCP；自動排程／Telegram；即時地圖與天氣；完整生理負荷模型；原生 App；收費及 AIAC 代管額度；大規模視覺重做。朋友若在手機上看不到或找不到重要操作，那屬於可用性，會優先修。付費前要先驗證教練品質、每次成本、每人配額與資料隔離。

本機已支援跨週、歷史課表、FIT 對應與備份，也可安排全身壺鈴間歇。若一堂課同時用 AIAC 和手錶記錄，可確認同時段活動屬於同一堂課，保留裝置數據，週總時間不重複計算。下一步用真實壺鈴紀錄驗證對應，再改善訓練後回顧。雲端保存、帳號與付款等試用後再決定。
